# 多路并行验证：反射层 vs 云端大模型（2026-10-22）

考卷（`experiments/bench_build.py`）：《懒》32 张图 + 23 条音频。
- S1：Gemini 审过的旧版 16 张（8 张有问题，3 张带英文字）
- S2：高清版 16 张，注入 4 张叠英文字、4 张换成别拍画面，另有 3 张已人工核实缺元素
- S3：4 个多音字（行/重/还/中）各一对一错的合成配音；15 条真实配音中 4 条被换成别拍音频

| 路线 | 做法 |
|---|---|
| A 反射层 | `tools/reflex.py`，Mac M4 本地，EmbeddingGemma 2 |
| C 云端大模型 | Hark 云端子代理逐张看图（看不到音频） |
| B Gemini（agy） | Mac 上 `agy --model gemini-4-argon-high`，三卷并行（经桌面会话 screen 桥接） |

## 结果
| 检查 | A 反射层 | C 云端大模型 |
|---|---|---|
| 有问题的画面（19 张） | 抓 16，误报 0 | 抓 17，误报 1 |
| 注入英文字（4） | 4/4，误报 0 | 4/4，误报 0 |
| 换错画面（4） | 4/4，误报 0 | 4/4，误报 0 |
| 旧版真实小字 | 3 张主要英文全中；漏 5b 信封手写和「No 88」 | 也抓到 5b；3b/3c 的车号、涂鸦记号算有字（可争议） |
| 多音字读错（8） | 8/8 全对 | 不能听 |
| 配错音频（15） | 4/4，误报 1（2b） | 不能听 |
| 全量耗时 | 129 s（冷启动，本地，0 费用） | 约 70 s（云端） |
| 改一拍后重检 | **3.9 s**，只重算 10 个嵌入 | 需要重看（按全量计约 70 s） |

各自独有的发现：
- 只有 A 抓到：S2_5c（缺「玻璃管里安睡的 Twin」）
- 只有 C 抓到：S1_2c（仪表盘画成圆钟）、S2_3b（Twin 没挥旗）
- 两路都漏：S2_0a（手在打字而不是悬在回车上）
- 两路合并：19 张有问题的画面抓到 18 张

说明：标签里旧版「有字」只按 Gemini 意见标了 3 张，复查发现 5b 确实有字（标签不全，已在此注明）。

## 结论
1. 画面检查上，局部对照式反射层已接近大模型逐张看图的水平（16 vs 17），且零误报。
2. 反射层独有的价值：改一拍 3.9 秒出结果（约快 18 倍）、本地零成本、能听（读音 8/8、配音错配 4/4）。
3. 两路错的不一样，合并后最好：反射层每次改动都跑；大模型只在定稿节点全量看，或专看反射层点名的元素。

## 补充：路线 B Gemini（2026-10-22 05:20）
| 检查 | B Gemini |
|---|---|

| 音频 | 读到一半被 Gemini 安全过滤拦截，无结果 |
| 耗时 | 并行墙钟 284 s（S1 184 s、S2 284 s） |

三路合并：19 张仍抓到 18 张，S2_0a 三路都漏。
注意偏差：S1 的标签本来就来自 Gemini 早先的审片意见，B 在 S1 上满分有主场优势；公平比较看 S2（A 9/11、C 10/11、B 8/11）。
结论补充：Gemini 擅长整体/字/换图，细小缺元素最弱；在这套题上它不比反射层多抓什么，却慢约 70 倍于改一拍重检，且音频这次不可用。
