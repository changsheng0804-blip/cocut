# 方法与实测

## 核心：先出预览样本，先改，最后渲染一次
目标是用最快、最低成本的方式先让人看到片子的主线，在草稿上改对，再花钱出图、渲染。衡量标准：从脚本到第一个能看的预览要多久、花多少；整部片子渲染了几次。

### 新样本《先改，再渲染》（examples/hello，9 拍 41 秒，2026-10-23，Mac mini M4）
| 步骤 | 耗时 | 花费 |
|---|---|---|
| 文字脚本 → 能播的草稿（doc.json + 9 句配音，并发） | 6.6–7.5 秒 | 0（edge-tts 免费） |
| 不配音的草稿（按字数估时长） | 0.1 秒 | 0 |
| 改一处读音（cocut→扣卡特）→ 只重配这一句 | 3.2 秒 | 0 |
| 9 拍成品帧快照（给不能看视频的 AI） | 10.8 秒 | 0 |
| 渲染 | 0 次 | — |

草稿阶段直接暴露的问题：旁白占 85%（太满，40 秒塞了 9 句）、总长多 1.1 秒、片名英文读音。都在草稿里一两步改掉，不需要出图或渲染。

# 《懒》Gemini 4 Argon（16 拍约 79 秒，2026-10-21/22）：草稿之后的提质流程

## 流程
1. **拍点表**：只写意图（每拍讲什么、谁、什么动作、时长）。
2. **交互草稿**：示意图 + 占位配音（字级时间）+ 配乐草切 + 字幕，浏览器实时合成。人在画面上点着留意见；AI 读同一份文件、看审片版、留同格式意见。
3. **多轮修改**：只改拍点表；改一句只重配一句；页面自动刷新。
4. **定型**：先做角色设定图（Twin）和色调卡（每幕配色 + LUT），图与视频共用一套色调。
5. **逐拍提质**：扩散模型以「构图参考 + 角色设定 + 色调卡」出电影化画面 → 统一套 LUT → AI 审画 → 按意见重出 → 超分。动态仍由代码控制（推拉/平移/视差），视频模型只留给少数重点拍。
6. **一次导出**。

## 预览与成片的差异（AI 审画结论）
- 景别、机位、核心视觉隐喻和节奏在草稿阶段已锁定，约占叙事效果的 85% 以上。
- 成片新增的是材质、光影和少量语义改进（如圆钟改为转速表）。
- 新风险主要来自**把草图直接喂给生成模型**：草图的歧义被放大（四角星、多一个角、纸底被当成白天）、参考图污染（照片里印出草图本身）、物理穿插。
- 对策：第二轮改用第一轮的电影化帧作构图参考（相当于「草图规范化」），13 拍一次修好。
